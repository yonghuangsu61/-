# 期权对账系统 - 后台管理页面

## 📋 系统概述

这是一个专业的期权对账系统后台管理界面，用于大量数据核对时支持多维度对账结果展示和Break分析，帮助业务人员快速定位和跟进问题。

## 🎯 核心功能

### 1. Dashboard 总览页 (`index.html`)
- **实时对账状态**: 展示今日对账成功数、Break数、待处理数和覆盖率
- **快速操作入口**: 提供多维度查询、今日Break、维度总览、历史查询的快速访问
- **趋势图表**: 显示最近7天的对账趋势
- **最近Break记录**: 列出最新发现的差异记录

### 2. 多维度对账查询页 (`reconciliation.html`)
- **灵活的筛选器**:
  - 日期选择（默认当天）
  - 大账户（1-10，支持多选）
  - 子账户（L/S）
  - 期权标的（Option Symbol）
  - 期权系列（Option Series）
  - 持仓类型（Long Call/Put, Short Call/Put，支持多选）
  - 交割类型（Exercise, Expiration, Assignment）
  - 交割物（Cash, Physical买入/卖出）

- **视图选项**:
  - 仅显示Break数据
  - 显示汇总数据
  - 明细视图 vs 汇总视图切换

- **数据展示**:
  - 详细的数据表格，支持排序
  - Break数据红色高亮显示
  - 分页浏览
  - 统计信息实时更新

### 3. Break分析页 (`break-analysis.html`)
- **Break概览**: 显示总Break数、待处理、处理中、已解决的统计
- **快速过滤**: 按优先级、差异类型、处理状态快速筛选
- **详细Break卡片**:
  - Break ID和优先级标识
  - 完整的期权信息
  - 对比视图（系统A vs 系统B）
  - 差异类型清晰展示（数量不匹配、价格差异、交割类型不匹配等）
  
- **处理功能**:
  - 标记为已解决
  - 深入调查
  - 升级处理
  - 添加处理备注
  - 查看处理历史

### 4. 历史查询页 (`history.html`)
- **灵活的时间范围选择**:
  - 自定义开始和结束日期
  - 快速选择（今天、最近7天、30天、3个月、1年）

- **趋势分析**:
  - 对账成功率趋势
  - Break数量趋势
  - 平均处理时长
  - 图表可视化

- **历史记录表格**:
  - 每日对账汇总
  - 处理状态跟踪
  - 操作人记录
  - 详情查看和数据导出

## 📊 对账维度说明

### 大账户
- 共10个大账户（账户1-10）
- 可以单独查询或多选组合查询

### 子账户
- L (Long): 多头账户
- S (Short): 空头账户
- 每个大账户下有两个子账户

### Option Symbol
- 格式示例: `AAPL 251226 127.00 CALL`
- 包含：标的、到期日、行权价、类型

### 持仓类型
- Long Call: 买入看涨期权
- Long Put: 买入看跌期权
- Short Call: 卖出看涨期权
- Short Put: 卖出看跌期权

### 交割类型
- Exercise: 行权
- Expiration: 到期
- Assignment: 被指派

### 交割物
- Cash: 现金结算
- Physical (买入): 实物交割-买入标的
- Physical (卖出): 实物交割-卖出标的

## 🚀 使用方法

1. **启动系统**:
   - 直接在浏览器中打开 `index.html`
   - 或部署到Web服务器

2. **查询对账数据**:
   - 从Dashboard进入"对账查询"
   - 设置筛选条件（默认显示当天数据）
   - 选择是否仅显示Break数据
   - 点击"查询"按钮

3. **处理Break**:
   - 从Dashboard或对账查询进入"Break分析"
   - 查看Break详情和对比数据
   - 添加处理备注
   - 标记处理状态

4. **历史分析**:
   - 进入"历史记录"页面
   - 选择时间范围
   - 查看趋势图和汇总数据
   - 导出报告

## 📈 数据对接建议

### 推荐接入的图表库
- **ECharts**: 适合复杂的趋势分析和多维度展示
- **Chart.js**: 轻量级，适合简单图表

### API接口建议
```javascript
// 对账查询
GET /api/reconciliation?date=2024-12-24&accounts=1,2&positionType=long_call

// Break列表
GET /api/breaks?status=pending&priority=high

// 历史记录
GET /api/history?startDate=2024-12-01&endDate=2024-12-24

// 更新Break状态
POST /api/breaks/{id}/resolve
```
